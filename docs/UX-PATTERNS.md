# Vertlix AI — UX Patterns

> **Официальный стандарт продуктовых паттернов.** Не компоненты, не страницы,
> не лендинг — готовые сценарии взаимодействия. **Каждый новый экран обязан
> собираться из этих паттернов.**
>
> Место в системе: [Philosophy](./DESIGN-PHILOSOPHY.md) → [Tokens](./DESIGN-TOKENS.md) →
> [Foundations](./FOUNDATIONS.md) → [Components](./COMPONENT-LIBRARY.md) → **Patterns** → экраны.
> Паттерны ссылаются на реальные флоу, уже реализованные в продукте.

**Версия 1.0 · 2026-07-22**

**Три цели каждого паттерна:** снизить когнитивную нагрузку · ускорить задачу ·
сделать поведение предсказуемым (Philosophy P16, P17).

**Формат документации (§18)** — каждый паттерн: *Purpose · User Goal · UX Logic ·
Components · Flow · Edge Cases · Accessibility · Best Practices · Anti-patterns · Do · Don't.*
Якорные паттерны раскрыты целиком; каталожные — в сжатой форме.

## 1. Authentication Patterns

Реализовано на NextAuth v5 (JWT, 30д), bcrypt(12), реальный TOTP 2FA, passkeys, подписанные самоистекающие токены.

### 1.1 Login (якорь)
- **Purpose:** впустить пользователя быстро и безопасно.
- **User Goal:** «войти за 5 секунд».
- **UX Logic:** OAuth-кнопки сверху (1 клик) → разделитель → email+пароль. Ошибки — обобщённые (не раскрывают, существует ли аккаунт).
- **Components:** OAuthButton×2, Input(email/password), Button(primary), OTP-step, ErrorBanner.
- **Flow:** ввод → `signIn(redirect:false)` → успех → `/dashboard`; если `2FA_REQUIRED` → второй шаг (OTP/backup-код) → `signIn` с `totpCode`.
- **Edge Cases:** OAuth-аккаунт без пароля (нет `password_hash`) → «войдите через Google»; неверный 2FA → счётчик, спокойное сообщение; rate-limit (10/15мин) → «слишком много попыток».
- **Accessibility:** `<form>`, label-ы, focus на первое поле, ошибки `aria-live`, OTP-поле `inputmode="numeric"`.
- **Best:** «запомнить устройство» после 2FA (планируется); passkey-кнопка. **Anti:** раскрывать «email не найден»; блокировать без объяснения.
- **Do:** обобщённая ошибка «неверный email или пароль». **Don't:** отдельные ошибки для email vs пароля (энумерация).

### 1.2 Register
- **Flow:** имя+email+пароль(≥8, буквы+цифра, индикатор силы) → создание (bcrypt 12) → авто-сессия → письмо верификации (best-effort). **Edge:** email занят → 409; демо-режим без БД → `{demo:true}`. **Do:** серверная проверка сложности = клиентской. **Don't:** блокировать вход до верификации (мягкий gate, не жёсткий).

### 1.3 Email Verification
- **Flow:** письмо со **подписанным self-expiring токеном** (24ч, purpose="verify") → `/verify-email?token` → авто-POST → success/expired. **Edge:** просрочен → resend по email (generic-ответ, без энумерации); reset-токен ≠ verify-токен (изоляция назначения). **Do:** «отправить снова». **Don't:** хранить токен в БД (он самодостаточен).

### 1.4 Forgot / Reset Password
- **Flow:** email → generic «если аккаунт есть — письмо отправлено» (без энумерации) → подписанный токен (1ч) → `/reset-password` → новый пароль (та же политика). **Edge:** нет `RESEND_API_KEY` → ссылка логируется (dev). **Don't:** подтверждать существование аккаунта.

### 1.5 Magic Link
- **Статус:** НЕ реализован (нужен email-провайдер). **Паттерн (целевой):** email → одноразовый подписанный токен → клик = вход. UX как reset, но вместо пароля — сессия. **Anti:** магик-ссылка без срока/одноразовости.

### 1.6 OAuth (Google / GitHub)
- **Flow:** клик → провайдер → callback → upsert в `users` → сессия. **Edge:** email конфликтует с password-аккаунтом → связать по email. **Do:** те же кнопки на login и register.

### 1.7 Two-Factor (TOTP)
- **Flow:** enroll (QR + secret, `--font-mono`) → подтверждение кодом → **backup-коды показать один раз** → включено. Логин: пароль верный → второй шаг. **Edge:** потерян телефон → backup-код (одноразовый, удаляется после); отключение требует пароль. **Best:** секрет шифруется (AES-256-GCM). **Don't:** boolean-тумблер без реального enforcement на входе.

### 1.8 Passkeys (WebAuthn)
- **Flow:** «Войти по passkey» → email → `startAuthentication` → верификация ассерции + counter (clone-detection). Управление в настройках (список/добавить/удалить). **Edge:** нет passkey у аккаунта → 404 «нет passkey». **Do:** passkey как ускоритель поверх пароля.

### 1.9 Session Expired
- **UX Logic:** middleware ловит отсутствие сессии → redirect `/login?callbackUrl=<текущий>`. **Best:** после входа вернуть на исходный экран. **Don't:** терять несохранённые данные молча — предупредить/сохранить черновик.

## 2. Onboarding Patterns

**Философская позиция (принята в продукте):** лучший онбординг — продукт, понятный
без тура. Навязчивое welcome-модальное окно было **удалено** осознанно (мешало, не помогало).

- **Welcome Screen:** короткий, пропускаемый, ведёт к первому действию — не тур по кнопкам.
- **Progressive Onboarding:** подсказки в контексте, по мере надобности (не всё сразу).
- **Empty Workspace:** это Empty State (§11), а не отдельный онбординг — иконка + «Создайте первый проект» + CTA.
- **AI Introduction:** знакомство с 20 директорами через первое реальное действие (создать стратегию → увидеть совет), а не слайд-шоу.
- **Workspace/Team Creation:** минимум полей, умные дефолты (Philosophy P16); организация создаётся автоматически при первом проекте.
- **Team Invitation:** см. §9.
- **Anti-patterns:** блокирующий многошаговый тур; форма из 10 полей на старте; «welcome» без действия.
- **Do:** value как можно быстрее. **Don't:** заставлять смотреть тур до работы.

## 3. Dashboard Patterns

- **Header (TopNav):** контекст (где я) + быстрый поиск/⌘K + аватар-меню. Sticky, `z-sticky`.
- **Sidebar:** постоянный ≥ lg, бургер/боттом < lg; разделы сгруппированы; активный подсвечен `--color-primary`.
- **KPI / Metric Cards:** число крупно (`tabular-nums`), дельта цветом-семантикой + иконкой, спарклайн. Summary раньше деталей (Foundations §—).
- **Widgets:** карточки одного каркаса, разный контент; grid 3→2→1.
- **Analytics/Charts:** семантика отдельно от акцента (dataviz-скилл); ось/сетка приглушены, endpoint выделен.
- **Activity Feed:** обратный хронологический, иконка-тип + текст + relative-time; пагинация/бесконечный скролл.
- **Quick Actions:** 1 primary + вторичные ghost; не более 3-4 в зоне.
- **Do:** дашборд ведёт к решению, не к созерцанию (Philosophy P1). **Don't:** «графики ради графиков».

## 4. CRUD Patterns

**Ядро продукта — паттерн «localStorage-first + optimistic + server-sync + best-effort fallback»** (vault, custom-agents, favorites, projects).

- **Create:** форма (§7-паттерн) → **оптимистичная вставка** в UI с временным `k-`/`c-` id → POST → замена на серверный UUID; при ошибке — откат + тост. Лимит плана — серверный (free 3 проекта → **402** + `upgradeUrl`).
- **Read:** мгновенный рендер из кэша → фоновая сверка с сервером (сервер авторитетен). Всегда 4 состояния (loading/empty/error/success).
- **Update:** inline или в модалке; оптимистично; **whitelist полей на бэке** (mass-assignment закрыт); скоуп по `user_id`/org.
- **Delete:** **подтверждение** (необратимое → Dialog + фраза), затем оптимистичное удаление + DELETE; предложить **Undo** (§14) где возможно.
- **Archive/Restore:** мягкое удаление (`is_deleted`), restore из архива — предпочтительнее hard-delete для пользовательских данных.
- **Duplicate:** клон с новым id, суффикс «(копия)», в тот же список (как cloneAgent).
- **Bulk Actions:** чекбоксы строк → плавающая панель «N выбрано» с действиями; подтверждение для деструктивных; прогресс при массовой операции.
- **Edge Cases:** оффлайн → кэш держит UI, синк при возврате; конфликт версий → сервер побеждает, уведомить.
- **Do:** оптимистичность = скорость (Philosophy P6). **Don't:** hard-delete без подтверждения/undo; доверять клиенту в лимитах/скоупе.

## 5. Search Patterns

- **Global Search / ⌘K (Command Palette):** одно поле, мгновенные результаты, группировка (проекты/действия/навигация), клавиатура ↑↓/Enter/Esc, recent сверху при пустом запросе.
- **Instant Search:** debounce 150–250мс, результаты по мере ввода, скелетон, «ничего не найдено» = осмысленный Empty (§11).
- **AI Search:** семантический поиск (планируется — нужен embeddings-ключ); честно помечать AI-результаты, показывать источники.
- **Filters/Sorting:** чипы активных фильтров с ×; сортировка — явный контрол, состояние в URL (шарится/восстанавливается).
- **Empty Search:** «Ничего по „запрос“» + предложить сбросить фильтры/примеры.
- **Edge:** очень длинный запрос — усечь; спецсимволы — экранировать. **Do:** сохранять состояние поиска в URL. **Don't:** терять фокус поля при обновлении результатов.

## 6. AI Patterns ⭐ (важнейший раздел)

Базовая аксиома: **вывод AI — untrusted до проверки; интерфейс помогает проверять, а не слепо доверять** (Philosophy P3). Реализовано: стриминг по токенам (SSE `chat/direct`), 20 директоров, ответы 7–12 предложений.

### 6.1 AI Chat (якорь)
- **Purpose / Goal:** получить экспертный ответ и понять его основание.
- **UX Logic:** сообщения читаемой ширины (~65 симв.), различимые роли, markdown-рендер, история, кнопка «остановить генерацию».
- **Components:** Conversation, StreamingMessage, PromptInput(⌘Enter), AgentCard, ReasoningBlock, CodeBlock, Citation.
- **Flow:** ввод → отправка → **ThinkingState** → **стриминг токенов** → done → доступны reasoning/sources.
- **Edge:** обрыв стрима → показать частичное + «продолжить/повторить»; пустой ответ; отмена пользователем.
- **A11y:** `aria-live="polite"` на потоке; остановка с клавиатуры; фокус остаётся управляемым.
- **Do:** стримить, не «ждать 20с». **Don't:** блокировать ввод во время генерации без «стоп».

### 6.2 Streaming Response
- **UX:** токен-за-токеном, курсор-пульс во время, чёткое завершение; авто-скролл вниз с уважением к ручному скроллу пользователя. **Tokens:** `--ease-standard`. **Anti:** фейковый прогресс вместо реального стрима.

### 6.3 Thinking State
- **UX:** три пульсирующие точки + «директор анализирует…», `--ease-in-out`; reduced-motion → статичный текст. **Don't:** спиннер без контекста; молчание.

### 6.4 AI Agent / Agent Status
- **UX:** 20 директоров — единый каркас, идентичность в аватар-цвете/имени/роли (Philosophy P15). Статус: `idle → thinking → done`. **Do:** показывать, кто отвечает и его зону. **Don't:** «зоопарк» из 20 стилей.

### 6.5 Prompt Builder / Suggestions / History
- **Builder:** multiline, submit ⌘Enter, вложения, счётчик; **Suggestions:** 3 контекстные подсказки-стартера; **History:** прошлые промпты, повтор/редактирование. **Don't:** терять черновик промпта при навигации.

### 6.6 Conversation & AI Memory
- **UX:** треды сохраняются; память — прозрачна (что модель «помнит»), с возможностью очистить. **Don't:** скрытая память без контроля пользователя.

### 6.7 AI Error
- **UX:** человеческим языком, причина + следующий шаг («не смогла обработать — переформулируйте»); **сырой текст провайдера скрыт** (безопасность + ясность). **Don't:** стектрейс в UI.

### 6.8 AI Confidence
- **UX:** честно. Высокая уверенность — прямая формулировка; низкая — «это гипотеза, проверьте»; **никаких фейковых процентов**. **Don't:** выдавать выдумку за факт.

### 6.9 AI Sources / Reasoning / Citation
- **UX:** обоснование и источники — вторичным текстом (`--color-text-secondary`), доступны, но не навязчивы; путь перепроверки. **Do:** «Показать рассуждение». **Don't:** чёрный ящик.

## 7. Settings Patterns

Реализовано: URL-синхронизированные вкладки (profile/ai/notifications/security/language/appearance), паттерн **Section(title/desc) + Row(label/desc/control)**, автосохранение в `/api/settings` и `/api/user`.

- **Profile:** имя, аватар (клиентский ресайз 256², превью), email (read-only). **Preferences/Appearance:** тема (dark/light/system) + акцент/плотность. **Notifications:** тумблеры email/push + детализация. **Security:** пароль, 2FA, passkeys, **журнал безопасности**. **API Keys:** создать/показать один раз/отозвать (маскировать). **Billing/Workspace/Organization:** §8, §9.
- **UX Logic:** каждая вкладка = URL (шарится, back работает); сохранение с тостом; опасное (удаление аккаунта) — с подтверждением пароля.
- **Do:** мгновенный feedback на сохранение. **Don't:** «Сохранить» без индикации результата; терять несохранённое при переключении вкладок.

## 8. Billing Patterns

Реализовано: серверные план-лимиты (free 3 проекта → 402 + `upgradeUrl`), LemonSqueezy webhook (HMAC).

- **Pricing:** планы карточками, выделен рекомендуемый (один акцент), фичи сравнением. **Upgrade:** триггерится лимитом (402) — контекстный, «перейдите на Pro для безлимита». **Downgrade:** предупредить, что потеряется; в конце периода. **Payment Failed:** спокойный баннер + «обновить карту», grace-период, не отрубать резко. **Invoice:** список + скачивание PDF. **Usage Limits:** прогресс к лимиту заранее (не сюрприз на 100%).
- **Anti-patterns (запрещено):** тёмные паттерны — таймеры-угрозы, «осталось 2 места», скрытая отмена подписки (Philosophy P2/P17). **Do:** лимит показан заранее и enforced на сервере. **Don't:** доверять клиенту в лимитах; резко блокировать при сбое оплаты.

## 9. Team Patterns

- **Invite Member:** email + роль → приглашение (подписанная ссылка); pending-состояние. **Remove:** подтверждение + переназначение владельца при необходимости. **Roles/Permissions:** owner/admin/moderator/support/user; UI скрывает недоступные действия + бэк проверяет (никогда только UI). **Workspace/Org Switcher:** dropdown с текущим контекстом, поиск при многих, «создать новую».
- **Edge:** последний owner нельзя удалить/понизить; повторное приглашение. **Do:** права проверяются на сервере. **Don't:** прятать кнопку как «защиту» без серверной проверки.

## 10. Table Patterns

- **Sorting:** клик по заголовку, индикатор направления, состояние в URL. **Filtering:** чипы активных фильтров с ×. **Pagination:** страницы или бесконечный скролл (большие наборы — виртуализация). **Selection:** чекбоксы + «выбрать всё на странице». **Bulk Actions:** плавающая панель «N выбрано». **Row Actions:** hover-иконки или «⋯»-меню; деструктивные — с подтверждением. **Expandable Rows:** раскрытие деталей без ухода со страницы.
- **Responsive:** мобила → карточки «label: value» или `overflow-x: auto` внутри контейнера (страница не скроллится вбок). Числа — `tabular-nums`, вправо; заголовок sticky.
- **Do:** состояние таблицы (сорт/фильтр/страница) в URL. **Don't:** горизонтальный скролл всей страницы на телефоне.

## 11. Empty States

Структура (Foundations §14): **иконка/иллюстрация → заголовок (1 фраза) → пояснение (1–2 строки) → один CTA.** Тон приглашающий, не «ошибка».

| Контекст | Заголовок | CTA |
|---|---|---|
| Нет проектов | «Создайте первый проект» | + Новый проект |
| Нет результатов | «Ничего по „запрос“» | Сбросить фильтры |
| Нет AI-ответов | «Задайте первый вопрос совету» | Открыть чат |
| Нет уведомлений | «Всё прочитано» | — (нейтрально) |
| Нет команды | «Пригласите коллег» | + Пригласить |
| Нет данных | «Данные появятся здесь» | Как это работает |

- **Do:** объяснить ценность и первый шаг. **Don't:** пустой экран / «No data».

## 12. Error Patterns

Тон спокойный, причина + путь; **сырой текст провайдера/БД скрыт** (реализовано в безопасности).

| Тип | Паттерн |
|---|---|
| **Network** | Баннер «Нет соединения» + авто-retry + оптимистичный откат |
| **Server (5xx)** | Full-state «Что-то пошло не так» + «Обновить»; лог в Sentry |
| **Validation** | Inline под полем, после blur, конкретно |
| **Permission (403)** | «Недостаточно прав» + к кому обратиться; не раскрывать лишнего |
| **AI** | «Не смогла обработать — переформулируйте»; стек скрыт |
| **Payment** | «Оплата не прошла» + «обновить карту», grace, не отрубать |

- **Do:** причина + действие + спокойствие. **Don't:** «FATAL ERROR: код»; вина на пользователя.

## 13. Loading Patterns

- **Skeleton:** структурированный контент — повторяет будущую раскладку (нет CLS). **Progressive:** критичное сверху раньше. **Lazy:** ниже сгиба по мере скролла. **Infinite Scroll:** подгрузка + «загрузка…» + защита от дублей; кнопка «загрузить ещё» как альтернатива. **Streaming:** AI по токенам. **AI Thinking:** §6.3.
- **Rule:** воспринимаемая скорость > реальной (Philosophy P6). `aria-busy` на загружающихся зонах. **Don't:** спиннер вместо скелетона для целой страницы; пустой экран.

---

## 14. Feedback Patterns

- **Toast:** результат действия, авто-скрытие 4с (error дольше), стек, `aria-live`. **Success/Warning/Error:** семантика `--color-*-bg/-border` + иконка + текст. **Confirmation:** для необратимого — Dialog с явной фразой действия. **Undo:** после удаления — тост «Удалено · Отменить» (5–7с) вместо жёсткого подтверждения где возможно (снижает трение).
- **Do:** лейбл действия = результат («Опубликовать» → «Опубликовано»). **Don't:** тост для критичного подтверждения; двойные уведомления одного события.

---

## 15. Navigation Patterns

- **Sidebar:** постоянный ≥ lg, группы, активный по `--color-primary`. **Navbar:** контекст + ⌘K + профиль, sticky. **Breadcrumb:** путь при глубине ≥ 2, последний — текущий (не ссылка). **Command Palette (⌘K):** быстрый доступ к действиям/навигации. **Keyboard Shortcuts:** документированы, ⌘K показывает список; не конфликтуют с браузером.
- **Do:** предсказуемость — навигация не «прыгает» (Philosophy P17). **Don't:** прятать основную навигацию за нестандартными жестами.

## 16. Mobile Patterns

- **Навигация:** сайдбар → бургер/боттом-таб-бар < lg; крупные тап-зоны (≥44px). **Модалки → BottomSheet** снизу. **Таблицы → карточки.** **Формы:** одна колонка, `inputmode`/`autocomplete`, клавиатура под тип. **Safe area:** `--safe-*` для notch/home-indicator. **Жесты:** свайп для второстепенного, не для критичного; всегда есть кнопочный аналог.
- **Do:** mobile-first, палец достаёт до действий (нижняя зона). **Don't:** hover-зависимые действия без tap-аналога; горизонтальный скролл страницы.

---

## 17. Accessibility Patterns (WCAG AA)

- **Keyboard:** весь функционал с клавиатуры; логичный tab-порядок = визуальный; Esc закрывает оверлеи; фокус-trap в модалке + возврат.
- **Focus:** `:focus-visible` всегда виден (`--shadow-focus`); никогда `outline:none` без замены.
- **Screen Readers:** семантический HTML; `aria-label` на иконочных кнопках; `aria-live` для тостов/стрима AI; заголовки по уровням.
- **Contrast:** текст ≥ 4.5:1; `--color-text-muted` — только meta.
- **Touch Targets:** ≥ 44×44px.
- **Do:** статус = цвет + иконка + текст. **Don't:** полагаться на цвет/hover/наведение как единственный канал.

## 19. Figma

- **Auto Layout:** флоу как фреймы-шаги, связанные Prototype-переходами.
- **Variables:** состояния паттерна (loading/empty/error/success) — через режимы/варианты, биндинг к Semantic-переменным.
- **Interactive Components:** hover/focus/pressed прототипируются (Smart Animate, `--ease-standard`).
- **Prototypes:** каждый паттерн — кликабельный флоу (login→2FA→dashboard; create→optimistic→synced; ⌘K→result).
- **Правило:** паттерн в Figma = последовательность экранов-состояний, а не один статичный кадр.

## 20. Quality Review (аудит)

| Критерий | Результат |
|---|---|
| **Масштабируемость** | ✅ Паттерны абстрактны от контента; новый экран = сборка из существующих |
| **Единообразие** | ✅ Общие правила (4 состояния, оптимистичность, generic-ошибки) на все флоу |
| **Отсутствие дублирования** | ✅ Один CRUD-паттерн на все ресурсы; один Empty/Error/Loading-стандарт |
| **Мировые практики** | ✅ Энумерация-safe auth, стриминг AI, оптимистичный UI, WCAG AA, честность лимитов |
| **Готовность к миллионам** | ✅ Серверный enforcement (лимиты/скоуп/rate-limit), оффлайн-устойчивость, no dark patterns |

**Найденные и устранённые при аудите слабые места:**
1. Риск рассинхрона с реальностью → все паттерны ссылаются на реально реализованные флоу (2FA, verify-email, план-лимиты 402, стриминг), а не на воображаемые.
2. Двусмысленность про непостроенное → magic-link и AI-семантический-поиск честно помечены «планируется (нужен провайдер/ключ)», а не выданы за готовое.
3. Риск тёмных паттернов в billing → явно вынесены в запрет (§8) со ссылкой на Philosophy.
4. Отсутствие единого CRUD-стандарта → зафиксирован паттерн «optimistic + server-sync + best-effort fallback» как обязательный (§4).

**Итог:** библиотека паттернов — официальный стандарт проектирования экранов Vertlix AI.
Любой новый экран собирается из §1–§17; отклонение требует явного обоснования и обновления
этого документа (паттерн либо становится правилом, либо не существует).
