# Vertlix — язык движения

Движение должно ощущаться как Linear / Vercel / Stripe / Raycast: **дорого,
намеренно, незаметно**. Каждая анимация объясняет переход или направляет
взгляд. Движения ради движения не существует.

## Единственный источник правды

```ts
import { DUR, EASE, T, fadeUp, stagger, REVEAL } from "@/lib/motion";
```

`src/lib/motion.ts` зеркалит CSS-токены из `tokens.css`. **Не писать литералы
длительностей в компонентах** — до появления модуля в проекте было 15+ разных
значений (0.22…1.2s) для одинаковых по смыслу движений.

| Шаг | Значение | Когда |
|---|---|---|
| `DUR.FAST` | 0.15s | hover, press, focus, смена цвета/непрозрачности |
| `DUR.MEDIUM` | 0.4s | появление элемента, смена состояния, модалка |
| `DUR.SLOW` | 0.7s | киношный вход, отрисовка графика, прогрессивный reveal |

Кривая по умолчанию — `EASE.standard` `[0.22, 1, 0.36, 1]` (ease-out-quint).
Она уже используется в 54 местах — не изобретать новую.
`EASE.spring` (с перелётом) — только для физичных мелочей: тосты, чипы.

Stagger между детьми — 60–110ms (`STAGGER.tight/base/loose`). Больше —
интерфейс «тормозит», меньше — эффект не читается.

## Готовые паттерны

`fadeUp` (основной вход) · `fadeIn` · `scaleIn` · `slideIn(from)` ·
`stagger(step)` · `hoverLift` · `press` · `modal` · `pageTransition`

## Нарратив продукта

Анимация первого экрана рассказывает ровно одну историю:

```
INPUT → ANALYSIS → INSIGHT → STRATEGY → ACTION
```

Тайминги этой последовательности — в `REVEAL`:

1. `REVEAL.panel` — панель приезжает
2. `REVEAL.bars` — метрики **вычисляются**: бар растёт, цифра считается
   тем же ease-out-cubic и финиширует одновременно с баром
3. `REVEAL.agents` — агенты отчитываются по очереди (stagger)
4. `REVEAL.verdict` — вердикт последним, это кульминация
5. `REVEAL.statusSwitchMs` — «Analyzing…» → «Analysis complete»

Смысл: пользователь видит не декорацию, а **как продукт думает**.

## Технические правила

- Анимировать только `transform` и `opacity`. `width/height/top/left` вызывают
  layout и роняют FPS. Исключение — уже оптимизированный `width` у баров.
- SVG-линия рисуется через `pathLength` 0→1 (Framer Motion), не через ручной
  `stroke-dasharray`.
- Бесконечные фоновые лупы — CSS keyframes, не JS: они идут в compositor и не
  держат main thread.
- Частицы — Canvas 2D + спрайт-блиттинг (см. apex-animations), не DOM-узлы.
- `will-change` — точечно и временно; постоянный `will-change` съедает память.

## Доступность

`globals.css` глушит CSS-анимации под `prefers-reduced-motion`, **но это
правило не достаёт до Framer Motion** — он анимирует инлайновые transform из
JS, и никакой стиль это не переопределит. Нужен один раз на всё приложение:

```tsx
import { MotionConfig } from "framer-motion";
<MotionConfig reducedMotion="user">{children}</MotionConfig>
```

Пока не подключено — это открытый пункт, см. vertlix-performance.

## Анти-паттерны

❌ своя длительность в каждом компоненте вместо `DUR`
❌ пружина везде — «прыгучий» интерфейс читается дёшево
❌ постоянное движение в фоне, конкурирующее с контентом
❌ parallax сильнее 6–8px
❌ анимация `width/height/margin` вместо `transform`
❌ вторая библиотека анимаций рядом с Framer Motion
