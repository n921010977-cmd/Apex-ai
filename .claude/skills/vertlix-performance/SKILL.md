# Vertlix — производительность и визуальный QA

Правило: **эффект не важнее отзывчивости.** Анимация обязана оставаться
плавной на среднем ноутбуке и телефоне, иначе она удаляется.

## Бюджеты

| Метрика | Цель | Что чаще всего ломает |
|---|---|---|
| LCP | < 2.5s | тяжёлый hero, неоптимизированная картинка, блокирующий шрифт |
| CLS | < 0.1 | картинка без размеров, шрифт без fallback-метрик, вставка баннера |
| INP | < 200ms | тяжёлый обработчик, синхронный setState в эффекте |
| FPS | 60 | анимация layout-свойств, `shadowBlur` в цикле, сотни DOM-частиц |

## Инструменты (уже настроены)

```bash
npm run qa:design                       # свип по 390/430/768/1024/1280/1440/1920
npm run qa:design -- / /pricing         # несколько страниц
npm run analyze                         # треемапы бандла в .next/analyze/
npx tsc --noEmit && npm run build       # обязательный минимум перед сдачей
```

`npm run qa:design` (`scripts/design-qa.mjs`) требует запущенный `npm run dev`
и ловит: горизонтальный скролл, элементы, вылезающие за вьюпорт (декор с
`aria-hidden` и обрезанное предком — игнорируются), обрезанный текст, ошибки
консоли и нарушения WCAG 2.1 AA через axe. Скриншоты — в `.design-qa/`.

**Скриншоты смотреть глазами.** Скрипт ловит механику, а не композицию:
наезжающие карточки и кривой ритм он не увидит.

## Картинки

- Только `next/image`; сырой `<img>` — лишь для того, что не проходит через
  оптимизатор. Сейчас в проекте 4 сырых `<img>` — это долг, eslint о них ругается.
- `formats: ["image/avif", "image/webp"]` включён в `next.config.ts`.
- Всегда задавать `width`/`height` или `fill` + контейнер с `aspect-ratio` —
  иначе CLS.
- Hero-картинка: `priority`, остальное — ленивое по умолчанию.
- `deviceSizes` покрывает 390…3840, включая 2x/3x для телефонов — размытый
  hero обычно означает отсутствие нужного шага, а не низкое качество исходника.
- `sizes` обязателен для `fill`, иначе браузер тянет самый широкий вариант.

## Шрифты

`next/font` самохостит Inter / Manrope / JetBrains Mono — внешних запросов нет,
CSP их и не пропустит. Не добавлять `@import` с Google Fonts: это блокирующий
запрос и мгновенный CLS.

## Анимации и рендер

- Анимировать `transform`/`opacity` (compositor), не layout-свойства.
- Бесконечные лупы — CSS, не JS (см. vertlix-motion).
- Тяжёлые секции ниже первого экрана — через `next/dynamic`; в `page.tsx` это
  уже сделано, новые тяжёлые секции добавлять так же.
- Ререндеры: следить за `setState` внутри эффектов (eslint уже предупреждает
  «Calling setState synchronously within an effect» — это долг, не шум).

## Открытый пункт: reduced-motion

`globals.css` глушит CSS-анимации, но **Framer Motion этим не управляется**.
Пока не обёрнуто в `<MotionConfig reducedMotion="user">`, пользователи с
включённым «уменьшить движение» всё равно получают все входные анимации.
Готовая инструкция — в конце `src/lib/motion.ts`.

## Открытый пункт: контраст

Замер axe на `/` (1440): **26 нарушений `color-contrast`**, ratio 2.08–4.46
при пороге AA 4.5. Причина — текст на низкой непрозрачности
(`text-white/25` … `text-white/45`), в основном в футере. Правило на будущее:
для смысловой информации не светлее `rgba(255,255,255,0.55)` на фоне `#05060B`;
`white/35` и ниже — только для чисто декоративных подписей.

## Анти-паттерны

❌ вторая библиотека анимаций «на всякий случай»
❌ 3D/WebGL ради фонового градиента (Canvas 2D / CSS дешевле на порядок)
❌ подмена нативного скролла без явной причины (бьёт INP и доступность)
❌ `priority` на всех картинках сразу — это отменяет приоритизацию
❌ «у меня не тормозит» вместо замера
