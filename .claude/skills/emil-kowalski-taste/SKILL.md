# Impeccable Design Taste — по мотивам Emil Kowalski

Кредо: **великая анимация невидима.** Если пользователь заметил анимацию —
скорее всего, она слишком заметна. Вкус = сумма деталей, которые по отдельности
не видит никто, а вместе они дают ощущение «сделано профессионалами».
Эталон: iOS, Linear, Vercel, Family, Arc, работы Emil Kowalski / Rauno / Paco.

## 1. Движение (motion)

### Easing — самое важное решение
- **Вход элемента → `ease-out`.** Быстрый старт, мягкое торможение. Элемент
  «прилетает и оседает». Наш токен: `[0.22, 1, 0.36, 1]`.
- **Уход элемента → `ease-in` или быстрый `ease-out`.** Уходит охотно, не тянет.
- **НИКОГДА `ease-in` на появление** и **`linear` на что-либо кроме
  бесконечных циклов** (спиннер, marquee). `linear` на входе = дёшево.
- Реальные объекты не стартуют на полной скорости и не тормозят мгновенно.
  Любой переход имеет ускорение и замедление.

### Spring вместо duration для интерактивного
- Всё, что следует за жестом/вводом (drag, toggle, layout-сдвиг, поповер у
  курсора) → **пружина**, не фиксированная длительность. Пружина знает про
  скорость и прерывание.
- Дефолт: `type: "spring", stiffness: 300, damping: 30` (снап без разболтанности).
  Мягче — `stiffness: 210, damping: 26`. Для «живого» отклика — bounce чуть выше.
- Duration-переходы оставляем для «тупых» появлений (fade-in секции).

### Длительность
- UI-микропереходы: **150–250 мс.** Больше 300 мс на hover/tap = ощущается лагом.
- Крупные оркестрованные сцены — исключение, но дроби их на фазы.
- Правило: **чем чаще действие, тем короче анимация.** Кнопка, которую жмут
  сто раз в день, не может анимироваться 400 мс.

### Прерываемость
- Анимация обязана прерываться на полпути и лететь в новое состояние без
  «доиграю-потом-начну». Spring + `layout` во Framer Motion это дают из коробки;
  самописные `setTimeout`-цепочки — нет, поэтому для интерактива их избегаем.

### Exit-анимации — это половина качества
- Появление без ухода = вещь дёргается при исчезновении. Всегда `AnimatePresence`
  + осмысленный `exit`. Уход обычно короче входа.

### Origin и трансформа
- Анимируем **`transform` и `opacity`**, почти никогда `width/height/top/left`
  (они не на GPU и дёргаются). Раскрытие — через `scale`/`layout`, не `height`.
- `transform-origin` должен совпадать с точкой «рождения» (меню из кнопки растёт
  из угла у кнопки, а не из центра экрана).

## 2. Детали, которые отличают дорогое от шаблонного

- **Оптический центр, не математический.** Иконка внутри кнопки часто требует
  −0.5–1px, чтобы выглядеть центрированной. Треугольник «play» сдвигают вправо.
- **Оптическое выравнивание границ:** круглые/засечённые формы слегка выпускают
  за край (overshoot), иначе кажутся меньше соседних прямоугольных.
- **Радиусы вложены правильно:** внешний радиус = внутренний + padding. Вложенная
  карточка внутри карточки не может иметь тот же радиус, что контейнер.
- **Тени — слоями и по расстоянию.** Не одна тень, а 2–3: близкая контактная
  (маленький blur, заметная) + дальняя мягкая. Цвет тени — нейтральный, не чёрный
  в лоб. Выше объект — больше и мягче тень.
- **Границы — hairline.** `rgba(255,255,255,0.06–0.1)` на тёмном, а не сплошной
  серый. Свет сверху: верхняя грань чуть светлее (`inset 0 1px 0 rgba(255,255,255,.05)`).
- **Тап-таргеты ≥ 44px**, даже если визуально иконка 16px — добиваем зоной клика.
- **Курсор говорит правду:** `pointer` только на кликабельном, `text` на тексте,
  `not-allowed` на disabled. Неверный курсор = мелкая ложь, которую чувствуют.
- **Числа — `tabular-nums`** везде, где они меняются или стоят в столбик, чтобы
  не прыгала ширина.
- **Фокус виден и красив:** кастомный `:focus-visible` (кольцо в цвете акцента),
  но никогда не `outline: none` без замены.

## 3. Типографика вкуса
- Один-два шрифта, строгая шкала. Заголовки — плотнее трекинг
  (`letter-spacing: -0.02em`), крупный вес; капс-лейблы — наоборот, разрежены
  (`+0.08–0.14em`), 10–11px.
- Длина строки основного текста ~60–75 символов. `text-wrap: balance` на заголовках.
- Межстрочный 1.5–1.7 для тела. Плотные простыни текста — признак «не дизайнили».
- Контраст по иерархии, не по размеру: 3 уровня прозрачности текста
  (`0.9 / 0.5 / 0.3`) вместо пяти размеров.

## 4. Цвет и сдержанность
- **Один акцент.** Всё остальное — нейтрали с лёгким подмесом акцента в тени/фон,
  а не чистый серый. Семантика (success/warn/danger) — отдельно от акцента.
- Насыщенный цвет — точечно (одна кнопка, один график), фон и рамки приглушены.
- Никаких неоновых glow, радужных градиентов текста, тяжёлого glassmorphism —
  это первые маркеры «шаблона».

## 5. Пустые и переходные состояния
- Пустое состояние проектируется раньше заполненного: заголовок + одно действие,
  не «нет данных».
- Skeleton вместо спиннера, если структура известна. Спиннер — последнее средство.
- Оптимистичный UI: действие отражается мгновенно, откат — если сервер против.
- Каждое действие даёт обратную связь ≤100 мс (нажатие, тост, изменение состояния).

## 6. Доступность = часть вкуса
- `prefers-reduced-motion` → статичные финальные состояния для каждой авто-анимации.
- Контраст ≥ WCAG AA. Клавиатурная навигация проходит везде.
- Анимация никогда не мешает прочитать/нажать; она короче, чем время реакции.

## Чек-лист «дорого или дёшево»
1. Вход на `ease-out`, уход есть и короче? Интерактив на spring?
2. Ничего не анимируется дольше ~250 мс из частых действий?
3. Анимируются только `transform`/`opacity`? Origin в точке рождения?
4. Тени слоями, границы hairline, радиусы вложены?
5. Один акцент, нейтрали с подмесом, никаких неон/радуга/тяжёлый glass?
6. `tabular-nums`, правильные курсоры, видимый `:focus-visible`, тап ≥44px?
7. `prefers-reduced-motion` и контраст AA?
8. Убери анимацию совсем — интерфейс всё ещё понятен? (должен быть — да)

## Анти-паттерны (мгновенно читаются как «непрофи»)
❌ `linear`/`ease-in` на появлении ❌ анимация `height/top/left`
❌ переходы 400 мс+ на hover ❌ нет exit-анимаций ❌ спиннер вместо skeleton
❌ одна плоская чёрная тень ❌ мульти-акцент и неон ❌ `outline: none` без замены
❌ прыгающая ширина чисел ❌ `cursor: pointer` на всём подряд
